Bug log

Real bugs I tracked down while building these projects.

Model fix · Fund Flow

Averaging the graph signals hid the worst fraud

My first graph score was the sum of three rule flags divided by three, so a clear round-trip scored low whenever the other two rules were quiet. I switched to a severity-weighted maximum (round-trip 0.9, structuring 0.8, fan-out and fan-in 0.7). The final score now takes the higher of the model blend and the graph score.

Bug fix · Fund Flow

Postgres silently lowercased my columns

After moving from SQLite to Postgres, nameOrig and nameDest raised KeyError. Postgres folds unquoted identifiers to lowercase, so my camelCase columns no longer matched the code. Quoting the identifiers in the data layer fixed it.

Evaluation fix · DocQuery

My ground truth was misleading the metrics

The first evaluation matched answers by keyword, which paraphrasing made unreliable. I verified the real page numbers with a script and made a strict source-and-page match the primary metric. On that metric, Recall@5 went from 76.7% (dense) to 86.7% (rerank) to 90.0% (hybrid plus rerank).

Bug fix · DocQuery

One question searched every PDF I had uploaded

The vector collection was global, so a chat searched across all uploaded PDFs, which could also leak one user's documents into another user's answers. I scoped both the vector retrieval and the BM25 index to the chat session ID.

Bug fix · SkillBridge

The free LLM quota ran out

The Mistral quota ran out, so I moved the LLM calls to Groq. Two API keys now act as one shared pool: key 1 is tried first and the app falls back to key 2 automatically. Per-user daily limits (50 chatbot messages, 10 roadmaps, 5 mock interviews, counted per interview rather than per AI call) stop one user from draining the pool.

Testing · SkillBridge

Putting the app under automated tests

I added a test suite to SkillBridge: 34 Python tests and 33 browser-side validation checks. Both run in CI on every push.

Case study

Fund Flow Fraud Detection

Problem
Only 0.13% of transactions are fraud, and fraudsters work in rings. A row-by-row model misses the pattern across accounts.
Built
30 engineered features (structuring, threshold flags, velocity, balance mismatch). An Isolation Forest and two XGBoost models, blended with NetworkX checks for fan-out, round-trips and structuring. TreeSHAP explains each prediction.
Product
FastAPI and Postgres backend with single, batch and CSV scoring, upload history, a PyVis graph view, and a guest mode so recruiters can try it without signing up. OTP email and Google sign-in. A security pass added XSS fixes, rate limits and hashed reset tokens.
Result
F1 0.89 and PR-AUC 0.95 on the held-out set, after a leakage audit lowered the original numbers.
Trade-off
PaySim is synthetic and the India payment-rail context (UPI, NEFT, RTGS, IMPS) is an overlay, not real bank data. It has no organic round-trips, so I tested the graph rules on injected fraud chains.

Case study

DocQuery

Problem
Dense-only retrieval kept missing exact terms such as names, codes and clause numbers, and most PDF chat tools send your files to a server.
Built
Hybrid retrieval: vector search and BM25, fused with Reciprocal Rank Fusion, then reranked. Answers stream with source-file and page citations.
Result
Strict Recall@5 rose from 76.7% to 90.0% on a 30-question evaluation set.
Privacy
Parsing, embeddings, retrieval and Ollama inference all run on your machine. Hosted providers are optional, not the default.
Trade-off
The evaluation set is small, so read the numbers as directional.
